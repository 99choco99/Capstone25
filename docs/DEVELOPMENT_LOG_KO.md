# Capstone25 개발 기록

이 문서는 포트폴리오에서 프로젝트의 변화 과정을 빠르게 확인할 수 있도록 주요 작업만 남긴 기록입니다.

## 2025년 2월–3월: 플레이와 전투 기반

- 플레이어 이동, 점프, 슬라이드 구현
- NPC 상호작용 UI와 초기 적 행동 트리 구성
- 콤보 공격, 패링, 적 체력 UI 구현
- 루트 모션과 JSON 기반 통신 연결

이 시기에는 기능을 빠르게 붙이는 데 집중했습니다. 이후 전투 상태가 늘면서 입력, 이동, 전투 책임을 나누는 방향으로 구조를 바꿨습니다.

## 2025년 4월–5월: RPG 시스템

- 퀘스트와 대화, NPC 상호작용 흐름 확장
- 인벤토리, 장비·소비 아이템, 프로필과 스탯 구현
- UI 연출과 아이템 데이터 구조 정리

아이템과 공격 데이터를 ScriptableObject로 옮겨 수치 조정과 실행 로직을 분리했습니다.

## 2025년 7월–11월: 전투 확장과 온라인 기능

- 콤보, 회피, 가드 애니메이션과 공격 패턴 확장
- 상점 거래와 인벤토리·퀘스트 REST API 연결
- 타겟팅, 자세, 패링을 포함한 플레이어·적 전투 구조 개편
- Timeline 기반 처형과 사운드·이펙트 연출 추가
- 대형 FBX와 텍스처를 Git LFS로 이동

기능 수가 늘면서 한 클래스가 여러 책임을 갖는 문제가 생겼습니다. 상태 클래스와 공통 전투 인터페이스를 도입해 전이 조건과 피해 처리를 분리했습니다.

## 2026년 4월–5월: 초기화와 카메라 구조 변경

- 로그인 API와 게임 시작 부트스트랩 분리
- 씬 전환 전 데이터 준비와 플레이어 생성 순서 정리
- 직접 계산하던 카메라를 Cinemachine으로 교체
- 씬이 바뀔 때 카메라 참조가 사라지는 문제를 동적 참조 방식으로 수정

카메라는 플레이어 Follow를 유지하고 Aim만 전환하는 구조로 바꿨습니다. 락온 해제 시 카메라가 갑자기 돌아가는 현상을 줄이고 씬별 수동 연결도 없앴습니다.

## 2026년 7월: FreeCam·LockOn·처형 카메라 통합

- 자유 시점 입력과 락온 자동 추적을 하나의 OrbitalFollow 궤도에서 전환
- 모드 변경 시 입력 관성과 Yaw·Pitch 속도 보정
- 타겟과 플레이어의 화면상 높이를 이용한 락온 구도 조정
- 처형 이벤트와 Cinemachine Priority 블렌딩 연결
- 전투 상태, 프리팹, 애니메이터와 테스트 씬을 함께 갱신

현재 작업본은 `develop`에 보존했습니다. 변경 범위가 큰 만큼 `main`에 바로 합치지 않고 Play Mode와 빌드 확인 뒤 병합할 예정입니다.

## 작업하면서 정리한 원칙

- 기능 추가와 엔진·에셋 재직렬화는 가능한 한 다른 커밋으로 나눕니다.
- 카메라처럼 씬 의존성이 큰 시스템은 런타임에 참조를 연결하고 전환 전후 상태를 명확히 저장합니다.
- 성능 개선은 코드 변경만으로 완료 처리하지 않고 Profiler 결과를 함께 남깁니다.
- 전투 상태 전이, 패링 판정, 데이터 초기화는 Edit Mode·Play Mode 테스트 대상으로 우선 분리합니다.
